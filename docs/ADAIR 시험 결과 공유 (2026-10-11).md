## 파트 6 — UAV·UGV·총괄 20분 통합 운용

최종 후보 38aa911로 돌린 run\_20261011\_181821이 통과했습니다. 신고부터 두 자원 반납까지 1082 s 걸렸고, 수동 개입은 없었습니다.

시나리오 흐름은 이렇습니다.

1. 환경에서 화재 신고 (60 s) → 총괄이 자동 초기 정찰 과제를 만듦
2. 총괄이 UAV에 평가 → Safety 허가 → 실행 순서로 배정
3. UAV가 화재 칸 상공에서 600 s 감시 → 모의 관측(불 확인) → 환경에 반영
4. 운용자 역할이 지상 지원 요청 → 총괄이 UGV 평가·Safety·실행
5. UGV 도착·도로 상황 보고 → 총괄이 거점 복귀 지시 → 복귀 완료·READY일 때 반납
6. UAV 착륙·시동 해제 → 반납 → 점유 0으로 종료

| 항목 | UAV | UGV |
| --- | --- | --- |
| 안전 | 최소 지형 여유 85.2 m | 차체 도로 이탈 0, 전복 0 |
| 주행·비행 | 순항 9.98 m/s, 목표 10 m 안 614.5 s | 화재 칸 경계까지 최소 334.5 m |
| 끝맺음 | 거점 2.3 m 착륙, 지면 위 −0.02 m (착지) | 거점 대기 지점 복귀 |

- **미션 시작 항목 기록**: 읽기 전용 기록기로 확인했습니다. UGV 미션 2건(접근 35지점·복귀 45지점) 모두 시작 항목 0(차 앞 5.0 m)이었고, PX4는 0 → 1 → 2 순서로 진행해 되돌아가지 않았습니다.
- **같은 코드의 1차 실행(run\_20261011\_173931)은 무효**입니다. 총괄이 신고 과제를 35분 동안 배정하지 않았고, 원인은 찾지 못했습니다 (통합 6회 중 1회).

- **LLM 판단 시험 (별도 1회)**: 관측 계획 LLM을 켜고 돌렸습니다. LLM 호출 1회(35.2 s)에 위반·대체 동작 없이 UGV 3지점을 정했고, 993 s에 정상 종료했습니다. 다만 LLM이 고른 지점까지의 경로는 미리 검증한 경로가 아니라서, 발표 시연은 LLM을 끄고 합니다.

## 파트 7 — 총괄·환경 연동과 통신 단절

총괄과 UGV를 묶은 배정·인계·막힘 처리는 통과했고, 통신 단절은 정지·복귀 시작까지만 확인했습니다.

| 시험 | 방식 | 결과 |
| --- | --- | --- |
| 정상 순환 (배정→도착→완료→해제→복귀) | Gazebo 4대 | 1차에서 복귀 결함 2개 발견 → 고친 뒤 통과 (4대 거점 READY 948 s) |
| 주행 중 고장 → 다른 차로 인계 | Gazebo | 고장 차는 점유 유지, 같은 차 재배정 없음, 다른 차가 인계 |
| 막힌 차 반복 배정 | sim으로 결함 확인 → Gazebo | 고친 뒤 ROAD\_BLOCKED로 거절하고 대기 — 통과 |
| 통신 단절 (가짜 시계) | 자동 시험 | 10분 뒤 정지 → 30분 뒤 복귀, 경로 없으면 운영자 개입 — 통과 |
| 통신 단절 (실제 시계) | Gazebo | 600 s 뒤 임무 취소·정지, 정지 1800 s 뒤 복귀 시작. 복귀 경로 39.3 km라 **거점 도착은 미확인** |
| 화재 이격 (실제 환경 스냅샷) | 환경 서버 | 화재에서 450.3 m 떨어진 곳에 도착, 이탈 0. 같은 입력으로 같은 결정 재현 |

- 시험 중 총괄 결함 하나를 고쳤습니다. 추적할 시도가 없으면 UGV 서버에 연락하지 않아, 600 s 뒤 UGV가 통신 단절로 오판하고 멈추던 문제입니다.
- 장거리 평가 시간은 소방차 B→A 최대 82 s에서 9.4 s로 줄였습니다. 총괄 제한이 10 s라 여유가 작습니다.
- 통신 단절 복귀 경로가 유턴 금지 때문에 39 km까지 길어질 수 있습니다. 운영 정책을 정해야 합니다.
