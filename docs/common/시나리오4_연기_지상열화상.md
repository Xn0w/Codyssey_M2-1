# 시나리오 4. 연기로 UAV 열화상 관측 실패 → UGV 지상 열화상 대체 관측

> 작성 2026-10-05 (UGV 담당). 상태: **초안**. 아래 "구현 상태" 표의 미구현 항목이 채워져야 자동으로 돈다.

## 목적

공중 센서가 **도착은 했지만 관측에 실패**했을 때, 총괄이 같은 실패를 반복하지 않고 다른 종류의 자원(UGV)으로 원래 Task Requirement(열화상 관측)를 다시 충족시키는지 검증한다.

- 시나리오 3(강풍)은 **출발 전** 거절(Local REJECT)이다. 이 시나리오는 **도착 후** 관측 실패라는 점이 다르다.
- 관측 실패도 정보다. "연기 때문에 못 봤다"는 사실을 기록하고, 그 칸을 "불 없음"으로 바꾸지 않는다.

## 초기 상황 (2019-04-04 인제 남면 재현, 트윈 시각 기준)

| 항목 | 값 | 근거 |
|---|---|---|
| 발화 | 14:45, 남전약수터 인근 (칸 `13_101`) | 강원 산불백서 p.139, 환경 트윈 `NAMJEON_SPRING` |
| 바람 | 160°(남남동에서 불어옴), 5.7 m/s → 연기는 **북북서(340°)** 로 | 기상청 ASOS 인제(211) 14:00 |
| UAV | A-uav1·A-uav2, 발화점 700 m 앞 집결지에서 대기 | `tools/run_twin.sh` (TWIN_LAUNCH=forward) |
| UGV | A-ugv1, 인제119 대기 (목표까지 직선 약 4.8 km, 도로 약 5.3 km) | `ugv/data/road_network.json` |
| 감시 대상 칸 | `12_97` — 발화점에서 바람 불어가는 쪽 약 360 m, 설악로 노드 `494948`에서 43 m | 도로망·격자 계산 |
| 총괄 설정 | `ORCH_UGV_THERMAL=1` (UGV 지상 열화상, 모의) | `orchestrator/config.py` |

`12_97`을 고른 이유: 연기가 흘러가는 방향이면서, 도로에서 지상 열화상 범위(차 중심 ±225 m) 안에 들어오는 칸이다. 바람 불어가는 쪽 칸 대부분은 산속이라 UGV가 볼 수 없다. 이 시나리오는 **UGV가 볼 수 있는 칸에서만** 성립한다는 점을 그대로 둔다.

## 발생 이벤트

화세가 커진 시점(약 15:10, 백서상 대응 1단계 15:13)에 총괄이 확산 예측으로 바람 불어가는 쪽 칸 `12_97`에 **감시(열화상) Task**를 만든다. Requirement는 `THERMAL`, 허용 자원은 `UAV, UGV`다.

## 진행 과정

1. 총괄이 `12_97` 감시 Task를 생성한다 (THERMAL, UAV·UGV 허용).
2. 후보를 직선거리 순으로 평가한다. A-uav1(1 km 이내)이 UGV(직선 약 4.8 km)보다 앞이다.
3. A-uav1이 Local ACCEPT → Safety ALLOW → 출동 → 목표 상공 도착.
4. **모의 열화상 관측 결과 `OBSCURED`** (사유 `SMOKE_PLUME`).
   - 판정 근거를 관측 기록에 남긴다: 어느 불타는 칸에서 나온 연기인지, 풍향, 목표까지 거리.
   - 환경에는 "관측 시도, 가려짐"으로 반영하고, 칸 상태를 "불 없음"으로 바꾸지 않는다.
5. Task를 다시 연다. 사유 `OBSERVATION_OBSCURED:SMOKE_PLUME`.
6. **재평가에서 공중 자원을 뺀다.** 같은 칸·같은 사유로 이미 실패했으므로, A-uav1과 A-uav2 모두 `AIR_OBSCURED`로 후보에서 제외된다. 남은 후보는 A-ugv1이다.
7. A-ugv1 Local 평가: 가장 가까운 도로 노드 `494948`로 스냅, 경로와 ETA를 계산해 ACCEPT.
8. Safety ALLOW → 실행. 관제판 LIVE 화면에서 UGV가 인제119 → 설악로로 주행한다.
9. 도착 → **모의 지상 열화상** (`ASSUMED_GROUND_VIEW_V1`, 차 중심 450 m 정사각형).
   - 지상 수평 시야는 연기층 아래라 가려지지 않는다고 가정한다 (아래 "가정" 참고).
   - 결과: `12_97`이 타고 있으면 `DETECTED`, 아니면 `NOT_DETECTED` (둘 다 유효한 관측).
10. 환경 반영 ACK → Task 완료. 판단 화면에 "공중 관측 실패 → 지상 자원 대체" 이력이 남는다.

## 실패·예외 시 동작

| 상황 | 기대 동작 |
|---|---|
| UGV도 도착 위치가 목표에서 범위 밖 | 관측은 남기고 Task는 대기로 돌린다 (`NO_COVERAGE`, 지어내지 않음) |
| 도로가 막혀 UGV가 갈 수 없음 | Local REJECT `TARGET_UNREACHABLE` → Task 대기 `NO_FEASIBLE_CANDIDATE` |
| `ORCH_UGV_THERMAL` 꺼짐 | UGV가 `REQUIRED_CAPABILITY_UNAVAILABLE`로 빠짐 → Task 대기 |
| 바람이 바뀌어 연기가 걷힘 | 다음 재평가에서 공중 자원 제외를 풀어 드론이 다시 후보가 된다 |

## 검증 포인트

- 도착 후 관측 실패가 "완료"나 "불 없음"으로 잘못 처리되지 않는가
- 같은 원인(연기)으로 같은 종류 자원을 반복 투입하지 않는가
- 지상 자원이 원래 Requirement(THERMAL)를 실제로 충족하는지 다시 평가하는가
- 판단 이력(관측 실패 → 제외 사유 → 대체 자원)이 장부와 판단 화면에 남는가

## 기대 결과

연기로 드론 열화상이 실패해도 총괄이 UGV 지상 열화상으로 같은 칸을 관측하고, 그 과정과 근거가 기록된다.

## 가정 (모의, TEST_ONLY)

1. **연기 기둥 모델**: 불타는 칸에서 바람 불어가는 방향 ±30°, 1.5 km 이내 상공은 짙은 연기로 본다. 불타는 칸이 3칸 이상일 때만 적용한다. 실제 연기 확산 모델이 아니라 시험용 규칙이다.
2. **열화상과 연기**: 장파 열화상은 가시광보다 연기를 잘 투과한다. 그래서 이 시나리오는 "옅은 연기"가 아니라 **짙은 연기 기둥 안에서 수직으로 내려다볼 때**만 실패로 본다. 발표에서 이 가정을 밝힌다.
3. **지상 시야**: 지상 열화상은 연기층 아래에서 수평으로 보므로 가려지지 않는다고 본다. 지형에 의한 가림도 반영하지 않는다.
4. **속도**: UGV 주행 시간은 서버 설정 속도를 따른다. 출동 속도 조정(소방차 60 km/h, UGV 30 km/h 상한)이 반영되면 인제119 → `494948`이 약 11분(UGV)이다.

## 구현 상태 (2026-10-05)

| 항목 | 위치 | 상태 |
|---|---|---|
| UGV 지상 열화상 (모의) | `orchestrator/observation.py`, `config.py` (`ORCH_UGV_THERMAL`) | **있음** (`feat/thermal-road`, main 머지 대기) |
| 바람 불어가는 쪽 감시 Task 자동 생성 | `orchestrator/engine.py` 선제 감시 (`ORCH_PREEMPTIVE_MONITOR`) | 있음. 단 허용 자원이 UAV뿐이라 UAV·UGV로 넓혀야 함 |
| 연기 기둥 판정 → `OBSCURED` | `orchestrator/observation.py` | **없음** |
| 관측 실패 시 Task 재오픈 사유 기록 | `orchestrator/engine.py` | 부분 (재오픈은 있음, 연기 사유 없음) |
| 같은 칸·같은 사유 공중 자원 제외 | `orchestrator/prefilter.py` | **없음** |
| 도로 주행·도착 위치 보고 | `ugv/server.py` | 있음 |

미구현 3건은 모두 총괄 모듈이다. 기본값은 꺼진 플래그(예: `ORCH_SMOKE_OCCLUSION=1`)로 넣어 기존 시험과 동작을 바꾸지 않는다.

## 시연 방법 (구현 후)

```bash
ORCH_UGV_THERMAL=1 ORCH_SMOKE_OCCLUSION=1 ORCH_PREEMPTIVE_MONITOR=1 \
PY=$PWD/.venv/bin/python TWIN_SPEED=30 UGV_TIME_SCALE=30 bash tools/run_twin.sh
```

- 관제판 `http://localhost:8080/inje3d` (LIVE): 드론 출동 → 복귀 → UGV 출동
- 판단 화면 `http://localhost:8200/board`, 판단 이력 `GET /tasks/{task_id}/events`
  (`OBSERVATION: OBSCURED` → `TASK_REOPENED` → `CANDIDATES_FILTERED: AIR_OBSCURED` → `LOCAL_RESPONSE: A-ugv1 ACCEPT`)
