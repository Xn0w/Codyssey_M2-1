## 발견한 결함과 수정

**팀 `tools/twin_clock.py` 에 'LLM 응답 중 시계 멈춤' 이 없었다.**
- 총괄은 LLM 계획을 기다리는 동안 `/health` 의 `llm.in_flight` 를 1 로 보낸다. 개인 저장소 ADAIR 의 시계는 이 값을 보고 진행을 멈추지만(사용자 결정 2026-10-08), 팀 저장소 시계에는 이 부분이 빠져 있었다.
- 그래서 100배속에서 LLM 응답 약 23 s 동안 시뮬레이션이 약 39분(sim 540 → 2880 s) 흘렀다. 그사이 규칙 지시서가 자원·구역을 차지해 첫 계획이 `OBS_PLAN_DISCARDED NO_ASSIGNMENT_VALID_NOW` 로 버려졌다 (원인: `BLOCK_NO_LONGER_SELECTABLE`, `RESOURCE_NO_LONGER_AVAILABLE`).
- 수정: ADAIR 의 `_wait_llm` 과 `--orch`·`--no-llm-pause` 옵션을 그대로 옮겼다. 총괄이 응답하지 않으면 멈추지 않고 진행한다. 멈춘 시간은 배속 기준 시각에서 뺀다.

## 트윈 통합 상세

실행: `python run_servers.py start --twin` (`.env` 에 키가 있으면 총괄 관측 계획이 LLM 을 쓴다).

| 실행 | LLM 호출 | 채택·실행 | 계획 폐기 | 채택 계획 안에서 빠진 배정 (통째 / 일부 구역) | 지연 (s) |
| --- | --- | --- | --- | --- | --- |
| 수정 전 (logs/twin/20261017_082757) | 5 | 4 (sim 5400·10680·14700·20100) | 1 (sim 2880, 배정 4건 전부) | 1 / 5 | 25.3 / 42.4 / 20.2 / 31.8 (폐기분 기록 없음) |
| 수정 후 (logs/twin/20261017_090756) | 5 | 5 (sim 720·2160·4260·6360·8460) | 0 | 8 / 4 | 42.2 / 32.1 / 41.6 / 20.7 / 21.1 |

- 빠진 배정은 OBS_PLAN 의 `dropped_assignments` 기준이다. 통째 = `RESOURCE_NO_LONGER_AVAILABLE`·`BLOCK_NO_LONGER_SELECTABLE`, 일부 = `SOME_BLOCKS_NO_LONGER_SELECTABLE`.
- 수정 후 첫 계획(sim 720)은 배정 4건 중 3건이 통째로 빠지고 1건만 일부 구역으로 실행됐다. sim 6360·8460 계획도 드론 배정이 `RESOURCE_NO_LONGER_AVAILABLE` 로 빠졌다.
- 즉 시계 수정은 '계획 전체 폐기'를 없앴지만, 호출 중 자원이 움직여 배정이 빠지는 문제는 해결하지 못했다 (아래 남은 한계).

- 두 실행 모두 규칙 대체(RULE_FALLBACK)·`OBS_LLM_WALL_TIMEOUT`·서버 Traceback 0건.
- 수정 전 실행의 LLM 배정은 모두 출동했다 (일부는 `WAITING_RESOURCE` 뒤 출동). `SAFETY_JUDGEMENT REJECT SNAPSHOT_CHANGED` 3건은 바로 재평가되어 ALLOW.

## 남은 한계 (시험으로 확인 안 됨)

- 시계를 멈춰도 `input_changed_during_call=True` 는 계속 나온다. mock 드론·UGV 는 실제 시각으로 움직이고, 총괄은 LLM 을 기다리는 동안에도 규칙 지시서(HEAD 추종)를 계속 내보내므로(`engine.py` `_call_while_dispatching_orders`) 배정이 빠진다. 팀 수정 후 실행에서 통째 8건·일부 4건, 개인 저장소 ADAIR 같은 구성 실행(logs/twin/20261017_083651)에서도 첫 계획 배정 3건 중 2건이 통째로, 넷째 계획 일부가 빠졌다.
- UAV 운용 상당 부분은 여전히 규칙(HEAD 추종·`RULE_AFTER_CHARGE`)이 정한다. 수정 전 실행 sim 14700·20100 계획은 드론 2대가 가용인데 UGV 에만 배정했다.
- 이번 실행에서 타는 칸이 0~1칸뿐이라 계획 품질을 평가하기에는 확산 정보가 빈약하다.
- 규칙 대체·시간 초과·잘못된 계획(repair) 경로는 실제 호출로 확인하지 않았다 (가짜 모델 단위 시험만 있음).
- `test_live_llm.py` 는 예전 `propose()`(우선순위 묶음) 경로만 부른다. 트윈이 쓰는 `plan_observations()` 실호출 시험은 없다.
