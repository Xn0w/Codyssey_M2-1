### 1.1 ① `test_route_corners_are_smoothed_into_drivable_arcs` — S6 가 깨뜨린 시험 코드 (정당한 기대 변경)

사실:

- 시험은 다듬기 전 선형을 재기 위해 `DriveGraph._smooth` 를 **클래스 수준에서** 람다로 바꾼다 (`ugv/tests/test_stage3_direction.py:374`):

- S6 는 `build_route` 에서 `self._smooth(pts, vlim, legs, relax, sel)` 로 **6 인자** 를 넘긴다 (`drive_graph.py:680`, 새 매개변수 `sel`). → `TypeError: ... takes from 4 to 5 positional arguments but 6 were given`.

최소 수정: `lambda self, pts, vlim, legs, *a, **k: (pts, vlim)`.

검증: 시험 파일을 임시 폴더로 복사해 람다만 위처럼 고친 뒤 S6 코드(`PYTHONPATH=ADAIR_wt_s6`)로 그 시험 1개를 실행 → **`1 passed, 19 deselected in 139.92s`** (그중 약 95 s 는 S6 그래프 빌드). 즉 S6 의 대안 원호가 이 시험의 기하 판정(다듬기 전 급꺾임 수 > 다듬은 뒤, 차체 모서리 도로 띠 안)을 바꾸지는 않는다 — 시그니처만 문제다.

### 2.2 원인 (코드)

`drive_graph.py:_build_turns` 가 회전마다

1. `turn_fit` → `_fit_candidates` 생성기를 **큰 반경부터 첫 통과까지** 소비 (기준과 같은 비용), 그리고
2. `turn_alternatives(…, R0, deg, vmax)` → **같은 `_fit_candidates` 를 처음부터 다시 만들어 리스트 컴프리헨션으로 13개 반경 전부 소비** (`cands = [... for R, m in self._fit_candidates(...)]`).

2 에서 큰 반경 쪽(기본 반경 포함)은 1 과 중복 평가되고, 기본보다 작은 반경은 통과하는 것마다 원호 + 앞뒤 방향선 자세 검사를 끝까지 한다 (실패 후보는 `m < floor` 에서 일찍 끊기므로 싸다). 대안은 3개(접선 ≤ 3/4·1/2·1/4·T0 의 첫 후보)만 쓰는데 평가는 전부 한다.

### 2.3 결과를 바꾸지 않는 최소 수정 (제안)

`_build_turns` 에서 생성기를 **한 번만** 만들어 이어 쓴다:

```python
gen = self._fit_candidates(u, w, strips, Lin, Lout)
primary, best = None, None
for R_, m_ in gen:                       # turn_fit 과 동일: 여유 이상인 첫(가장 큰) 반경
    if m_ >= need: primary = (R_, m_); break
    if best is None or m_ > best[1]: best = (R_, m_)
...
if primary is not None:
    th = math.tan(math.radians(deg) / 2)     # 기존 turn_alternatives 와 같은 산술(deg 경유) — 비트 동일을 위해
    T0 = R * th
    cands = []
    for R_, m_ in gen:                   # 같은 생성기 이어서 → 더 작은 반경만 나온다 (R_ < R0 자동 만족)
        if m_ >= need and R_ * th < T0 - 0.5:
            cands.append((R_, R_ * th, m_))
            alts = pick(cands)           # 기존 frac 선택 로직 그대로
            if len(alts) == TURN_ALT_MAX:
                break                    # 앞 선택은 뒤(더 작은) 후보로 바뀌지 않으므로 여기서 멈춰도 결과 동일
```

- 중단 조건의 정당성: 선택은 `.75 → .5 → .25` 순으로 "조건을 만족하는 **첫** 후보(이미 뽑힌 것 제외)" 이고 후보는 접선 내림차순이므로, 뒤에 후보를 더 붙여도 이미 확정된 선택은 바뀌지 않는다. 3개가 채워진 순간 결과가 확정된다. 3개가 안 채워지면 지금처럼 끝까지 소비한다 (여유 미달로 대체 반경을 쓴 회전은 `m >= need` 후보가 없으므로 대안 없음 — 기존과 같다).
- 주의: `T`·`th` 는 기존처럼 `math.radians(deg)` 를 거쳐 계산해야 **비트 동일** 하다. `ad/2` 로 직접 계산하면 접선이 마지막 자리에서 달라지고, R_STEPS 비(3.0/4.0 = 0.75)가 정확히 3/4 인 회전에서 `x[1] <= T0*0.75` 판정이 뒤집힌다 (스크래치 1차 시도에서 실제로 5개 회전의 대안이 바뀌어 확인; 산술을 맞춘 뒤 동일 — §2.4).
- `turn_fit`·`turn_alternatives` 메서드는 그대로 두어도 된다 (시험 `test_turn_alternatives` 가 `_fit_candidates` 를 직접 쓴다).

### 2.4 제안 수정의 동일성·효과 검증 (몽키패치, 원본 무수정)

스크래치 `fix_probe.py`: S6 코드로 UGV 그래프를 원래 `_build_turns` 로 1회, §2.3 의 단일 순회 `_build_turns` 로 1회 만들어 회전표 전체(`to, v_turn, deflect_deg, radius_m, tangent_m, margin_m, alts`)·`blocked_turns`·`tan`·`tan_min` 을 비교.

| | 원래 S6 | 단일 순회 |
|---|---|---|
| UGV 그래프 빌드 (동시 부하 중) | 120.8 s | **72.4 s (×1.67)** |
| 회전표 1,802 상태 / 2,510 회전 | — | **완전 동일 (`turn table identical: True`)** |

- 1차 시도(접선을 `tan(ad/2)` 로 계산)에서는 5개 회전의 대안이 달랐다 (예: 상태 `('682500260','494835')` 의 첫 대안 R 14.03 ↔ 10.29 — R_STEPS 3.0/4.0 = 정확히 0.75 라 `T <= 0.75·T0` 가 마지막 비트에서 갈림). `math.radians(deg)` 경유로 산술을 맞추자 동일. **적용 시 이 산술 유지가 필수.**
- 남는 비용(기준의 약 3.5배)은 대안 자체의 비용이다: 통과 반경 1개(기준) 대신 평균 4개(기본 + 대안 3)를 끝까지 자세 검사한다. 결과를 바꾸지 않고 더 줄이려면 §2.5 (시험 모듈 간 그래프 공유 또는 캐시) 가 필요하다.
- 예상 전체 시험 시간: UGV 5회 × ~55 s + 소방차 ~90 s ≈ 6 min 그래프 + 시험 본체 ~5 min ≈ 11~12 min (현 18 min). §2.5 그래프 공유까지 하면 ≈ 7~8 min.

### 2.5 그 밖의 선택지 (결과 불변)
